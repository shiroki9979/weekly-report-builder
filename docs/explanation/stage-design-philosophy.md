# Stage 設計哲學：Editorial Observatory

建立日期：2026-11-07

最後更新：2026-11-07

狀態：Advisory；所有 Deck Theme、Structured Layout 與 Stage Element 的上游依據，不是規格

---

## 這份文件的角色

本文件借用「先寫設計哲學，再以視覺表達」的兩段法：先定義 Stage 的美學世界觀，之後每個主題、版型與元素都以它為準，而不是各自發明一套外觀。它回答「這個 Stage 應該長什麼樣、為什麼」，不回答欄位、schema 或 CSS 怎麼寫；那些屬於 [Editorial Layout Family 規格](../specs/editorial-layout-family.md) 及後續規格。

哲學的對象是投影片，不是海報或藝術品。投影片必須在沒有講者時也能被讀懂（見 [好的 Slide](slide-design-research.md) 的雙情境原則），所以文字不是裝飾，資訊密度也不以「少」為美；這裡追求的是每一個元素都有可說明的作用，並以一致的手法安放。

領域名詞依 [CONTEXT.md](../../CONTEXT.md)：Deck Theme、Structured Layout、Layout Variant、Stage Element、Editorial Frame、Boundary Note、Tradeoff Callout。

## 宣言

**Editorial Observatory（編輯式觀測）**：把每一頁當成一份觀測紀錄來排版。結論是標題，證據是正文，條件寫在邊界。頁面的骨架來自編輯設計（eyebrow、結論式標題、欄位、細線），頁面的氣質來自科學圖表（編號、參照記號、刻度般的細線、克制的單一強調色）。讀者應該感覺這一頁是被仔細整理過的，而不是被裝飾過的。

**空間與形**：空間先於內容。每一頁都有固定的外框——上緣的標頭區、下緣的頁尾區、左右等寬的內距——內容只在它們之間流動，不越界也不懸掛。形狀以矩形與直線為主；圓角只用於需要被辨認為「可拿起的單位」的東西（卡片、標籤），不用在版面分割上。區隔靠留白與一條細線，不靠粗框與陰影。頁與頁之間，標頭的高度、頁尾的位置、內距的寬度都不跳動，翻頁時視線不需要重新定位。

**色彩與材質**：一張紙、一種墨、一種強調色。紙是白的，墨是深藍灰而不是純黑，強調色是沉穩的青綠；強調色的淡洗（wash）與淺調（soft）只用來標出「這一塊是被挑出來的」。狀態語意（positive、caution、neutral）有自己的三種墨色，和強調色分工：強調色指「看這裡」，狀態色說「這是好是壞」。沒有漸層，沒有陰影，沒有照片般的材質——材質來自紙白、墨色與細線三者的對比。任何一頁最多只有一個被強調色實色填滿的區塊。

**尺度與節奏**：字級只有少數幾個穩定角色——結論標題、正文、標籤／記號、頁尾——每個角色在整副 Deck 裡保持同一尺寸，不因內容多寡縮放。長度靠內容取捨與分頁解決，不靠縮小字級。節奏來自重複：同一種清單的項目間距相同，同一種欄的寬度相同，參照記號的位置固定。數字與記號可以用等寬字型，讓對齊本身成為一種秩序。

**構圖與平衡**：每一頁只有一個主焦點，它以尺寸、位置與留白取得優先，其餘內容以平靜的網格支撐它。不對稱是允許的——主焦點可以偏左、可以更大——但每個區塊的邊緣都要落在共同的格線上。兩欄比較時，兩欄等寬，被選定的一欄以一條強調色的線或一層淡洗區分，不以放大或換字型區分。表格的欄位對齊基線，參照欄靠右並以強調色呼應其他頁的編號。

**視覺層級**：第一眼看到結論式標題；接著看到被強調色標出的那一塊；細讀時才看到標籤、Boundary Note 與頁尾。eyebrow 說明這一頁的職能（Overview、Comparison、Closing），不說明內容；Boundary Note 永遠在正文之下、頁尾之上，以一條細線隔開，用來寫這一頁的結論在什麼範圍內成立。頁尾左側是 Deck Title，右側是頁碼，它們是定位記號，字級最小、顏色最淡。

**工藝標準**：成品應該像是被反覆調整過數十次的排版——每條線的粗細一致、每個間距可被解釋、每個對齊都是刻意的。沒有任何元素溢出畫布，沒有任何兩個元素互相壓到。加入一個新元素之前，先問「既有的元素能不能更精確地表達這件事」；精進一個版型時，先去掉多餘的，再調整剩下的，最後才考慮新增。

## 套用到 Stage 的約束

哲學是通用的；以下是它落在本專案時必須同時滿足的條件。規格若與這些條件衝突，以規格的決定為準並回頭修訂本文。

| 約束                   | 內容                                                                                                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 畫布                   | canonical capture Stage 1280 × 720 CSS 像素，PNG 以 `pixelRatio: 2` 輸出；Overflowing Page 不可匯出，哲學不能以「稍微超出」換取構圖。                                                       |
| 自行閱讀               | 單張 PNG 離開講者仍可讀；必要條件寫在 Boundary Note，不只放在 speaker notes。                                                                                                               |
| 對比                   | 關鍵文字對鄰接背景至少 4.5:1；狀態不可只靠顏色，須有文字標籤。                                                                                                                              |
| 狀態語意               | 每個 Deck Theme 都必須定義 Status Signal 的三種 tone（positive、caution、neutral）的墨色與淡洗；Overview 等既有版型依賴它們。                                                               |
| 字型                   | CJK 一律系統字型（Noto Sans TC、PingFang TC、Microsoft JhengHei 的順序），不內建。拉丁展示字型與等寬記號字型由主題決定；若使用，須自架 OFL 字型並驗證 PNG 嵌字。                            |
| 團隊簡報範本           | `default` 主題維持現行藍色與底部留白，讓 PNG 能貼進團隊 PPT 範本；本文件的色彩段落描述的是新主題，不改 `default` 的色票。                                                                   |
| Token 角色             | 主題以語意角色提供色彩：paper、ink、mute、line、accent、accent-deep、accent-soft、accent-wash、ok／ok-ink／ok-wash、warn／warn-ink。角色名稱是 HTML Page 的契約，命名與相容別名由規格決定。 |
| 既有 Structured Layout | 只接主題 token，不重排；構圖的改動另開 Layout Variant。                                                                                                                                     |

## 字型角色

| 角色       | 用途                                           | 新主題候選（原型驗證後定案）                                       |
| ---------- | ---------------------------------------------- | ------------------------------------------------------------------ |
| 結論標題   | 每頁的結論式標題、Cover 標題                   | 系統 CJK 字型，拉丁字可搭配 Instrument Sans 或 Bricolage Grotesque |
| 正文       | 要點、表格內容、解讀                           | 系統 CJK 字型                                                      |
| 標籤／記號 | eyebrow、欄標籤、參照編號、頁碼、Boundary Note | IBM Plex Mono 或與正文同字型的小字大寫                             |

原型要回答的字型問題只有兩個：拉丁展示字型與中文標題混排時，字重與基線是否協調；等寬記號是否讓參照編號更好找，還是只是多了一種字型。

## 審查提問

評估任何一頁是否符合本哲學時，依序問：

1. 第一眼看到的是結論式標題嗎？有沒有第二個區塊在搶同樣的優先權？
2. 被強調色標出的區塊只有一個嗎？它是這一頁最需要被看見的東西嗎？
3. 區塊的邊緣是否落在共同格線上？頁與頁之間，標頭與頁尾是否沒有位移？
4. 字級是否只用了既定角色，沒有為了塞內容而縮小？
5. 這一頁的結論在什麼範圍內成立，讀者找得到那一句嗎？
6. 去掉任何一個元素，資訊會不會變少？不會的話，它就不該在。
